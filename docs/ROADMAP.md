# ArcFlow 路线图

状态以代码和测试为准，以下阶段不构成发布日期承诺。

## 已实现：初始内核

- [x] Java 17 目标、无 Spring 核心、Apache 2.0
- [x] DAG 定义校验、同步串行执行、变量快照
- [x] Handler / Event SPI、示例和回归检查

## 实验性本地审批演示

独立于核心的示例层提供可编辑顺序审批：1–8 个指定审批步骤的增删、排序和发布，实例固定定义快照，按步骤推进、终态拒绝、授权后幂等重试，以及单进程 JSON 文件恢复。Vue 页面提供设计器、申请、待办、只读实例流程与历史。重复审批人允许出现在不同步骤，每一步必须单独提交决定；不提供条件分支、通用图形部署或生产持久化，也不表示下列核心能力已完成。见 [运行说明](../examples/approval-demo/README.md)。

## 已实现：可选 JDBC 事务存储首个切片

在既有窄范围顺序审批模型上，`approval-domain` 新增存储 SPI，`approval-jdbc` 提供 `arc_` SQL 表、不可变定义版本、请求修订号和独立审计事件的原子提交。多个服务实例之间通过数据库条件更新和短事务行锁协调；重复步骤决定重读已提交状态，不追加第二条事件。包含回滚、重开、并发和损坏检测测试，以及 PostgreSQL、H2 和实验性 MySQL 8 验证配置；MySQL 的提交幂等扩展须以精确提交的真实服务器测试结果为证，不能据此宣称生产支持。见 [模块契约](../examples/approval-jdbc/README.md)。

这是持久化基础切片，不是完整企业引擎。两个现有演示仍默认 JSON；尚无自动迁移、租户隔离、分页、联合业务事务、outbox 或调度器。下列通用引擎目标不因本切片而全部完成。

## 已实现：有界会签 / 或签领域语义

共享 `approval-domain` 的 schema 3 增加固定参与人组：ALL 全部同意 / 任一拒绝，ANY 任一同意 / 全部拒绝。每个参与人独立幂等，竞争决定仍通过原子修订号与审计追加提交。schema 2 定义与实例保持兼容；JSON 升级备份、JDBC 无 DDL 演进与回归边界见 [并行审批契约](PARALLEL_APPROVAL.md)。

独立 Vue / Spring Boot 示例已增加 Single / ALL / ANY 配置、参与人待办与逐人投票展示，保持顺序审批兼容；若依 HTTP / 原生界面也已增加真实用户分组、待办与逐人投票，仍保留自己的登录、菜单和权限体系。尚无动态加签、转办或通用分支汇聚，不能据此将下列完整企业审批目标标记为完成。

## 已实现：持久化提交幂等

两种 HTTP 主机支持可选申请人作用域提交键，同键同意图返回原申请当前状态，同键不同意图冲突。JSON 快照 schema 4 与 JDBC SQL revision 2 原子保存映射和申请；不带键保持旧行为，客户端保留页面内存中的未确认请求键。迁移、并发、重开与断电保证边界见[提交幂等契约](SUBMISSION_IDEMPOTENCY.md)。
