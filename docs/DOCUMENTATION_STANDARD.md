本标准适用于维护中的仓库文档与 API 资料。目标是让读者找到正确版本、完成任务、查到契约，并明确证据能证明什么。历史来源保留原貌，通过本地化入口解释范围。

<!-- topic:languages-and-naming -->
## 语言与命名

- 简体中文保留 `NAME.md`，英文为同目录 `NAME.en.md`；目录入口使用 `README.md`/`README.en.md`。保留已有稳定名称，不批量改路径只为统一大小写。
- 每页一个本地化标题、一个主要语言，顶部链接另一文件及所在目录。术语、代码标识、接口字段、测试名和逐字证据可保留原文。
- 中英文覆盖相同主题、字段、前提、步骤、命令、预期结果、风险和来源。允许自然表达，不要求逐句或段落长度相同；不能只给另一语言摘要。
- 语言导航直接指向配对文件。旧 `#zh`、`#en`、`#简体中文`、`#english` 可保留为兼容切换入口；旧章节片段需要显式锚点或有效目标，不能静默失效。
- `documentation-map.json` 按默认中文路径登记配对类别与稳定 topic ID。两种语言使用相同 `<!-- topic:identifier -->` 标识，顺序/结构调整时同时维护。

<!-- topic:page-types-and-organization -->
## 页面类型与组织

- **教程 tutorial**：带读者从初始状态完成一段可验证旅程。
- **操作 how-to**：已知目标的必要步骤、前提及恢复方式。
- **原理 explanation**：解释设计、取舍、边界与替代方案。
- **参考 reference**：精确字段、类型、限制、状态、错误、兼容和来源。
- **历史 history**：固定提交/日期/环境的实现或验收记录。
- **索引 index**：按读者任务导航，不复制完整契约。

分类优先在目录中表达，不为形式移动稳定文件。同页可包含必要补充，但应有一个主要目的；原理讨论不替代命令，测试结果不替代使用步骤。

<!-- topic:reusable-structures-where-useful -->
## 按需要复用页面结构

每页用标题和简短范围说明交代读者、对象与适用版本。其他部分只在有用时加入：

1. 运行/操作页：前提 → 步骤 → 可观察预期结果 → 常见失败与恢复 → 下一步。
2. 接口/数据参考：端点或类型 → 身份/权限 → 字段/限制 → 响应/错误 → 幂等/并发 → 存储兼容 → 来源/验证。
3. 设计说明：问题 → 选择和理由 → 明确边界 → 扩展位置与相关契约。
4. 证据页：日期/精确提交/tree/环境 → 已执行命令和结果 → 失败/跳过/未跑 → 原始产物来源 → 后续仍需的门槛。

不要给纯字段表硬加“操作步骤”，或给历史记录编造“预期结果”。尽量用短段落、含单位/类型的表和可直接执行的命令。前提和工作目录应放在命令之前。

<!-- topic:sources-of-truth-and-versions -->
## 事实来源与版本

- 当前行为以对应提交的代码、配置、controller/DTO、显式业务目录及可执行测试为准；README、图例或计划不能定义未实现端点。
- Java 工件版本、发布 tag、流程定义 schema、JSON wrapper、SQL revision 和业务 documentVersion 分别说明。当前 main 不是历史 alpha 标签；SQL 结构未变不代表旧二进制认识新载荷。
- 接口参考、OpenAPI、端点清单和请求样例必须与实际路由/校验/封装一致，改接口时一起更新；离线规范不暗示已部署 Swagger 或新接口。
- 当前源码范围与历史检查分段写明。保留真实失败、跳过、受阻和准确计数，不把 H2 当 PostgreSQL/MySQL，不把 DOM/HTTP 当浏览器，不把截图当事务或安全证明。
- 截图指向真实未改原图与逐图提交/运行/hash；语言变体不是不同业务状态。源码、CI、合并、发布、部署、生产验收是不同事实。
- 外部依赖维护状态注明核验日期并链接官方来源；没有新核验不要悄悄改日期或沿用过期“当前”。

<!-- topic:editing-and-translation-workflow -->
## 修改与翻译流程

先确定目标源码版本和受影响契约，再同步修改两种语言、目录、主题登记、示例及必要规范。保留代码/命令与技术标识；若更正旧事实，说明原检查点和当前边界，不改历史结果。翻译应核对所有数字、否定条件、字段必填性、范围、错误和恢复风险。

新增页面先明确主要类型和读者下一步。历史源原件不通过翻译重写，按[归档说明](history/README.md)登记来源；本地化维护页提供同等范围解释和访问路径。纯文档修改不得假定授权发布、合并、部署或改业务行为。

<!-- topic:before-submitting -->
## 提交前检查

- 两种语言主题和关键契约对齐，无遗漏章节、错误链接或混排段落。
- 相对路径、章节锚点、图片、源码及同语言导航有效。
- 命令工作目录、工具版本、数据保留/清理和副作用写清；不得包含真实凭据或个人数据。
- 运行仓库文档检查和相关接口/示例校验；报告真实执行范围，不把待执行清单写成通过结果。
- 人工复读语言、版本和边界。自动 topic/链接检查能发现结构遗漏，不能证明翻译语义或技术结论正确。
